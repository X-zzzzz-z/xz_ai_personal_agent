# XZ AI Personal Learning Agent

## 项目简介

XZ AI Personal Learning Agent 是一个面向学生和自学者的个人学习管理 Agent，用于记录学习内容、查询历史记录和检索 Markdown 学习笔记。

项目已接入大语言模型与 Tool Calling。用户通过自然语言提出需求，由模型选择工具，程序检查并执行工具，再将结果反馈给模型生成回答。

笔记检索采用基于文本向量的语义搜索，检索相关笔记片段，为模型回答提供上下文。

## 当前功能

- 通过自然语言添加学习记录。
- 按关键词或日期查询学习记录。
- 语义搜索 Markdown 学习笔记。
- 将学习记录保存到本地 JSON 文件。
- 检查工具参数的 JSON 格式和调用结构。
- 在学习工具中进行参数值校验及文件、JSON 异常处理。
- 使用统一的结果字典返回工具执行结果。
- 限制模型调用轮次，拦截重复搜索。
- 未检索到足够相关的笔记时，提示未找到相关内容。

## 技术与实现

- **Python**：工具开发、文件处理和 Agent 流程控制。
- **LLM API**：通过 OpenAI 兼容接口调用大语言模型。
- **Tool Calling**：由模型提出工具调用请求，程序执行对应函数。
- **Tool Schema**：描述工具名称、用途和参数结构。
- **Tool Registry**：保存工具名称与 Python 函数的对应关系。
- **Embedding 与语义检索**：将问题和笔记文本转换为向量，计算相似度并选取相关片段。
- **RAG**：将检索到的笔记片段反馈给模型，辅助生成回答。
- **JSON**：持久化保存结构化学习记录。
- **Markdown**：存放学习笔记。

## 项目结构

| 路径 | 作用 |
|---|---|
| `agent.py` | 接收用户输入，控制模型调用、工具执行和结果反馈 |
| `llm.py` | 配置模型客户端，封装模型请求 |
| `learning_tools.py` | 实现记录添加、记录查询和笔记搜索工具 |
| `rag.py` | 实现文本编码、相似度计算和语义检索 |
| `tool_registry.py` | 注册工具，按名称查找函数，获取工具 Schema |
| `tool_schema.py` | 为工具函数生成 Schema |
| `data/learning_records.json` | 保存学习记录 |
| `notes/learning_record_error_handling.md` | 学习记录工具的异常处理笔记 |
| `notes/agent_tool_calling.md` | Agent 与 Tool Calling 笔记 |
| `README.md` | 项目说明 |

## 核心流程

1. 接收用户问题，构建系统消息和用户消息。
2. 将消息列表和工具 Schema 发送给模型。
3. 保存模型返回的 assistant 消息。
4. 如果模型请求工具，解析工具名称和 JSON 参数。
5. 检查参数、查找工具函数，并执行工具。
6. 将工具结果封装为 tool 消息，通过 `tool_call_id` 关联对应请求。
7. 将更新后的消息列表再次发送给模型。
8. 模型返回普通回答后，输出回答并结束本次处理。

## 工具说明

| 工具 | 功能 |
|---|---|
| `add_learning_record()` | 添加学习记录并保存到 JSON 文件 |
| `query_learning_records()` | 按关键词或日期查询学习记录 |
| `semantic_search_notes()` | 语义检索 Markdown 笔记，返回相关片段 |

### 学习记录字段

| 字段 | 含义 |
|---|---|
| `date` | 学习日期 |
| `title` | 学习标题 |
| `content` | 学习内容 |
| `key_points` | 关键知识点 |
| `unresolved` | 未解决的问题 |

### 工具结果格式

工具使用统一的结果结构：

```python
{
    "success": True,
    "message": "执行结果说明",
    "data": ...
}
```

`success` 表示是否执行成功，`message` 提供结果说明，`data` 保存返回的数据。失败时返回对应的错误说明。

## 运行方法

### 1. 准备环境

当前已运行验证的环境：Windows、Python 3.13.15。

在项目根目录，使用选定的 Python 环境执行：

```bash
python --version
python -m pip install -r requirements.txt
```

安装依赖和运行程序应使用同一个 Python 解释器。使用 VS Code 时，通过“Python: Select Interpreter”选择项目环境。

首次运行可能需要下载文本向量模型：

`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`

模型调用需要网络连接和有效的 API Key。

### 2. 配置 API Key

在项目根目录创建 `.env` 文件，配置：

```env
DEEPSEEK_API_KEY=your_api_key
```

模型名称和 API 地址在 `llm.py` 中配置。不要将真实 API Key 提交到代码仓库。

### 3. 准备数据

将学习笔记放入 `notes/` 目录。

`data/learning_records.json` 使用 JSON 数组保存记录。新建空数据文件时，内容为：

```json
[]
```

### 4. 启动程序

在项目根目录执行：

```bash
python agent.py
```

根据终端提示输入问题。当前程序每次启动处理一个用户问题。

## 已完成的手动联调验证

| 场景 | 本次验证结果 |
|---|---|
| 搜索已有笔记 | 返回相关片段，模型生成回答并标注笔记来源 |
| 搜索无相关内容 | 提示未找到足够相关内容，没有补写该主题的解释 |

以上为当前测试样例的结果。尚未建立完整的自动化测试和检索质量评估。

## 当前限制

- 当前提供命令行交互，每次启动处理一个用户问题。
- 一个问题最多调用模型三次，第三次不再提供工具说明。
- 笔记搜索和记录查询各最多尝试一次，即使调用失败也会记录为已使用。
- 学习记录使用本地 JSON 文件存储，尚未实现数据库存储与并发写入控制。
- 检索效果依赖笔记内容、分块方式和相关性判断，需要更多样例验证。
- 无相关笔记时的回答行为受系统提示词约束，尚未经过大规模验证。
- 学习周报、月报和长期学习建议尚未实现。
